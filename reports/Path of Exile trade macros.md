# Price-check overlays cede currency to hourly data

As of September 2026, Path of Exile trade tooling has settled on a handful of free, open-source overlays. **Awakened PoE Trade (APT) is the PoE 1 standard, and its fork Exiled Exchange 2 (EE2) is the PoE 2 standard.** Sidekick is the one mature app that covers both games. All three work the same way: one hotkey simulates the game's Ctrl+C, the tool parses the item text from the clipboard, and it queries the undocumented `pathofexile.com/api/trade` endpoints under tight per-IP rate limits. They add poe.ninja and poeprices.info as secondary price sources. GGG tolerates this pattern without ever endorsing it. Its written rule is that a macro must be triggered manually and do exactly one game-affecting thing. Timers, screen-reading triggers, bots and anything that touches game files or memory are banned. The bigger shift is that the 3.25 Currency Exchange (Faustus) has no live API. The overlays therefore stopped pricing currency from trade-site listings, which the maintainers now consider dominated by pricefixers, and switched to poe.ninja ratios derived from GGG's **hourly Currency Exchange digest**. For pathofflipper, this means the project's core asset is the thing the whole ecosystem depends on but nobody archives for PoE 1: the hourly digest. poe.ninja keeps no history in its API, and GGG says old digests can be deleted. The safest and most distinctive product is a read-only analytics layer over that archive that never touches the game client.

## Two Electron overlays dominate a field of clipboard readers

GitHub signals put the current landscape beyond doubt. APT has **2,583 stars and 761 forks**, is MIT-licensed, and shipped v3.29.108 on 2026-09-09. It has released on every league launch from 3.25 through 3.29, for Windows, Linux and a universal macOS build ([APT repo](https://github.com/SnosMe/awakened-poe-trade), [APT releases](https://github.com/SnosMe/awakened-poe-trade/releases)). EE2 describes itself as a "Fork of Awakened PoE Trade" for PoE 2. It has 1,182 stars, and its v0.16.3 installer drew **201,114 downloads**, more than APT's latest at 154,559 ([EE2 repo](https://github.com/Kvan7/Exiled-Exchange-2), [EE2 releases](https://github.com/Kvan7/Exiled-Exchange-2/releases)). Sidekick is a C#/.NET app that runs a web app inside WebView2 and covers both games. Its latest installer was downloaded only about 3,500 times, although its update feed shows about 79,000 hits, so the gap is real but hard to size ([Sidekick repo](https://github.com/Sidekick-Poe/Sidekick), [Sidekick releases](https://github.com/Sidekick-Poe/Sidekick/releases)). These download totals are inflated by auto-updater files, and there is no reliable count of active users. No GGG statement or community poll calls any tool "the standard"; that status is inferred from these metrics.

The lineage matters. POE-TradeMacro, the AutoHotkey script that defined the genre, still points its README at the long-dead poe.trade. Sidekick credits it as the "Original Idea". None of these tools work on console, because they all depend on the PC clipboard and a desktop overlay.

## One keypress, one clipboard read, one unofficial API call

Item capture is simpler than the overlays look. APT sends a synthetic Ctrl+C through `uiohook` only while the game window has focus. It then **polls the clipboard every 48 ms for up to 500 ms**, accepts the text only if it starts with a localized `Item Class:` header, and can restore the user's previous clipboard within about 120 ms. It also throttles repeated actions so the game does not disconnect the player for "Too many actions" ([Shortcuts.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/main/src/shortcuts/Shortcuts.ts), [HostClipboard.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/main/src/shortcuts/HostClipboard.ts)). Since 3.29, a plain copy always includes the advanced mod description, so the parser always sees tiers and ranges. The parser splits the text on `--------` separators and runs a pipeline of section parsers. It maps mod lines to trade stat ids through bundled translation data ([Parser.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/renderer/src/parser/Parser.ts)). APT does tail `Client.txt`, but only to pass raw log lines to its widgets ([GameLogWatcher.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/main/src/host-files/GameLogWatcher.ts)). Nothing reads game memory.

The parsed item turns into calls to the **undocumented trade site API**. Items use `POST /api/trade/search/{league}` followed by `GET /api/trade/fetch/{ids}?query={id}`. Bulk currency uses `POST /api/trade/exchange/{league}` with a `{have, want, status}` body, and APT keeps the top 20 offers sorted by ratio ([pathofexile-trade.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/renderer/src/web/price-check/trade/pathofexile-trade.ts), [pathofexile-bulk.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/renderer/src/web/price-check/trade/pathofexile-bulk.ts)). The exchange response includes each listing inline, with seller account, online/AFK status, ratio and stock, so it needs no fetch step. The currency ids it accepts (`chaos`, `divine`, `alch` and so on) come from the CDN-cached [`/api/trade/data/static`](https://www.pathofexile.com/api/trade/data/static). Anonymous requests without a POESESSID cookie returned data on all three endpoints in live tests on 2026-09-23, and APT's trade code contains no cookie handling. GGG's developer docs do not mention this API at all ([GGG developer docs](https://www.pathofexile.com/developer/docs)).

Rate limiting is the real constraint. GGG reports its limits in headers: a policy name, a rule list, and `hits:period:penalty` triples with a matching `-State` header, plus `Retry-After` on HTTP 429 ([GGG developer docs](https://www.pathofexile.com/developer/docs)). Live anonymous requests on 2026-09-23 returned these limits:

| Endpoint | Policy | Per-IP windows (hits:seconds:lockout) |
|---|---|---|
| `POST /api/trade/exchange` | trade-exchange-request-limit | 5:15:60, 10:90:300, **30:300:1800** |
| `POST /api/trade/search` | trade-search-request-limit | 5:10:60, 15:60:300, 30:300:1800, 600:21600:3600 |
| `GET /api/trade/fetch` | trade-fetch-request-limit | 12:4:10, 16:12:300, 50:300:300, 1000:21600:1800 |
| `web.poecdn.com/api/currency-exchange` | none observed | CDN-cached for about a year per hour |

The exchange endpoint's five-minute window allows **about six currency-pair lookups per minute per IP**, and breaking it costs a **30-minute lockout**. That is enough for a human pressing a hotkey and far too little for a market scanner. APT deals with this by starting every category at one request per 5 s, rebuilding its sliding-window limiters from each response's headers, and refusing any request that would wait more than 1.5 s rather than queueing it ([common.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/renderer/src/web/price-check/trade/common.ts)). Secondary data fills in the rest. poe.ninja's documented `/poe1/api/economy/...` API serves exchange-derived and stash-derived overviews, refreshed about every 15 minutes for PoE 1. It asks for an identifying User-Agent with a contact and offers "no versioning and no SLA" ([poe.ninja API docs](https://poe.ninja/docs/api)). APT itself uses an undocumented "dense overviews" call every 31 minutes ([Prices.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/renderer/src/web/background/Prices.ts)). poeprices.info returns machine-learning price ranges for rare items and has nothing to do with currency ([poeprices.ts](https://github.com/SnosMe/awakened-poe-trade/blob/master/renderer/src/web/price-check/price-prediction/poeprices.ts)).

## GGG tolerates external tools but bans every form of automation

The binding rule is not in the Terms of Use but in the Developer Docs' Third-Party Policy. **"Macros must be invoked manually by the user"**, each invocation "must have one set function", and that function "must only perform one action that interacts with the game". Timer and screen-reading triggers are explicitly prohibited, and apps that interact with game files lead to immediate account termination. The same page calls websites and web apps the lowest-risk, recommended kind of tool ([PoE Developer Docs](https://www.pathofexile.com/developer/docs/index)). The Terms of Use, last updated October 2024, never mention macros. They ban bots (7c), connecting through anything other than the official client (7e), data-extraction tools against the website (7f), and reverse engineering of "communication protocols" (7i). Breaching them terminates the licence and allows account cancellation and IP blocks without notice ([PoE Terms of Use](https://www.pathofexile.com/legal/terms-of-use-and-privacy-policy)). Staff have drawn the same line informally for years: "It's okay to run things that are entirely external to the game," but not programs that "interact with the Path of Exile game client" ([Bex_GGG via devtrackers.gg](https://devtrackers.gg/pathofexile/p/cdea4d78-psa-waves-of-players-being-banned-for-use-of-third-party-tool-poe-overlay)).

This puts clipboard overlays in a **tolerated grey zone rather than an approved one**. APT's own FAQ says it does one server action per keypress with no memory access and no automation, and admits that GGG has never officially approved any community tool ([APT FAQ](https://snosme.github.io/awakened-poe-trade/faq)). The trade API they call is undocumented, which strictly falls under the 7i and 7f language even though GGG plainly tolerates low-volume use. The only well-documented enforcement against a trade tool supports this reading. In April 2020 PoE Overlay generated **6.7 million requests in one day, 6.1 million of them rate-limited**, and 5.9 million came from three accounts. Those accounts were temporarily locked for "hammering" the site, not banned for using the tool ([devtrackers.gg](https://devtrackers.gg/pathofexile/p/cdea4d78-psa-waves-of-players-being-banned-for-use-of-third-party-tool-poe-overlay)). The 2026 ban waves went unexplained and appeals ran past 11 days ([PoE forum thread 3925951](https://www.pathofexile.com/forum/view-thread/3925951)), which raises the cost of any grey-area automation. No public case ties a ban to a price-check overlay.

The official developer program is only partly open. Service scopes such as `service:psapi` (Public Stash API, which carries a five-minute delay) and `service:cxapi` (Currency Exchange) require a confidential OAuth 2.1 client. GGG states it is **"currently unable to process new applications"** ([Authorization docs](https://www.pathofexile.com/developer/docs/authorization), [PoE Developer Docs](https://www.pathofexile.com/developer/docs)). Registered apps must send `User-Agent: OAuth {clientId}/{version} (contact: ...)`. Frequent rate-limit breaches or floods of invalid 4xx requests can get access revoked "without notice". Tools must also carry the disclaimer "This product isn't affiliated with or endorsed by Grinding Gear Games in any way" ([PoE Developer Docs](https://www.pathofexile.com/developer/docs/index)). GGG also discourages hiding who is making requests: "We really don't condone tools obfuscating their user agent" ([devtrackers.gg](https://devtrackers.gg/pathofexile/p/cdea4d78-psa-waves-of-players-being-banned-for-use-of-third-party-tool-poe-overlay)). For flippers, the most important consequence is that **no official way exists to place Currency Exchange orders programmatically**. Auto-placing orders through the client would break both the macro rule and ToS 7c/7e. So would auto-whispering when a deal is detected, because the trigger would be automatic. Bots that do this exist, such as [FrozenTear7/poe-trading-bot](https://github.com/FrozenTear7/poe-trading-bot), and they are the clearest example of what not to build.

## Faustus pushed the overlays onto hourly digests and left flippers underserved

The Currency Exchange arrived with 3.25 Settlers of Kalguur. It is an asynchronous order book at Faustus: up to 10 listings, partial fills, and gold fees that rise with volume ([Maxroll Currency Exchange guide](https://maxroll.gg/poe/currency/currency-exchange-market)). Gold cannot be traded, which GGG designed as a defence against bots ([PCGamesN](https://www.pcgamesn.com/path-of-exile/currency-exchange-market)). The overlays could not read it. In July 2025 an APT user asked for Faustus prices and was told the data "is not available via API or trade site" ([APT issue #1628](https://github.com/SnosMe/awakened-poe-trade/issues/1628)). Asynchronous Merchant tabs arrived in 3.27, and APT's maintainer then **removed bulk-trade lookups** and made "Merchant Only" the default search. He argued that "the bulk trade is dead … all first 20 listings are pricefixers" and that GGG bars exchange-eligible items from Merchant tabs ([APT issue #1694](https://github.com/SnosMe/awakened-poe-trade/issues/1694)). Hardcore and private-league players objected, and he partly walked the change back behind a "Search anyway" button. The replacement price source came from the exchange itself via poe.ninja. EE2 adopted it in September 2025, APT in v3.27.106 in December 2025 ("Market Ratio on Currency Market Exchange (via poe.ninja)"), and the Overlay Community Fork in March 2026. Sidekick finally **removed trade search for exchange items** in v2026.9.1 ([APT releases](https://github.com/SnosMe/awakened-poe-trade/releases), [EE2 releases](https://github.com/Kvan7/Exiled-Exchange-2/releases), [Sidekick releases](https://github.com/Sidekick-Poe/Sidekick/releases), [Community Fork releases](https://github.com/PoE-Overlay-Community/PoE-Overlay-Community-Fork/releases)).

That source is GGG's public endpoint, `GET https://web.poecdn.com/api/currency-exchange[/<realm>][/<id>]`. For each hour it returns every market with `volume_traded`, `lowest_stock`/`highest_stock` and `lowest_ratio`/`highest_ratio`. GGG says "responses from this endpoint are purely historical", there is no current-hour data, and old history may be removed ([GGG API reference](https://www.pathofexile.com/developer/docs/reference)). pathofflipper's own measurements add detail. PC has no realm segment, and the current hour returns 404. Published hours are immutable (cached for about a year) and carry no rate-limit headers. History begins at 2024-07-26 20:00 UTC, and a recent hour held **about 1,300–1,600 markets across 8 leagues** ([exchange-api-observations.md](../specs/exchange-api-observations.md)). The whole ecosystem therefore prices currency on data that is **at least an hour old, with no order-book depth**. poe.ninja's API collapses each pair into one reference value plus a sparkline and **exposes no history** ([poe.ninja API docs](https://poe.ninja/docs/api)).

Flipping-specific tooling is thin. What flippers actually use is a patchwork. poe.ninja and [poe.watch](https://poe.watch/exchange) provide reference rates. [Exilence CE](https://github.com/exilence-ce/exilence-ce) tracks net worth. [Wealthy Exile](https://wealthyexile.com/) and PoExchange handle bulk selling. Whisper managers serve the non-stackable bulk the exchange does not take. The only PoE 1 exchange-specific helper found is [tirendus/poe-flipper](https://github.com/tirendus/poe-flipper), which has 0 stars. It screenshots the Market Ratio panel on Alt+Q, reads it with OCR, and suggests clean, divisible ratios at Fast, Fair and Greedy tiers. Its screen-reading design sits uncomfortably close to GGG's banned trigger type, though it is still started by a manual hotkey. The most sophisticated exchange analysis exists **only for PoE 2**. [poe2-faustus-arb](https://github.com/Faizak9x/poe2-faustus-arb) models the hourly digest as a graph with −log(rate) edges and runs Bellman-Ford to find arbitrage cycles above 2%. It filters to the top 10% of pairs by volume, prices each leg at the worst rate within the hour as a stand-in for the spread, and alerts only on cycles that last two consecutive hours. It never trades. Flipper guides, mostly written for PoE 2's identical exchange, list the pain points: capital lock-up, fills that take hours to days, thin markets, manipulation, and time-of-day swings such as "120-130 ex at certain times of day" ([Maxroll PoE2 flipping](https://maxroll.gg/poe2/resources/flipping-with-the-currency-exchange), [Steam discussion](https://steamcommunity.com/app/2694490/discussions/0/598516531140273041)). Players on GGG's forum ask directly for price-history graphs based on completed trades ([PoE forum thread 3855860](https://www.pathofexile.com/forum/view-thread/3855860)). Structural mispricings also appear. Ratio caps limited Rogue's Markers to about 65,000:1 against Divines, and flippers profited until players learned to route through Chaos ([zleague summary](https://www.zleague.gg/theportal/sirgog-how-flippers-exploit-the-currency-exchange-limitation-in-path-of-exile-settlers/); original article now 404). No reliable PoE 1-specific margin figures were found.

## pathofflipper already sits on the ecosystem's missing asset

The project's scope matches both where the rules are safest and where the market is thinnest. Fetching a public, unauthenticated CDN endpoint into PostgreSQL, and showing the results outside the game, is exactly the "entirely external" website-style tool GGG calls lowest-risk. It needs no clipboard capture, no hotkeys and no OAuth registration, which is closed anyway. Its immutable hourly archive also cannot be rebuilt from poe.ninja and could disappear from GGG. That makes **history-dependent analytics its defensible niche**: spread history per pair from `lowest_ratio`/`highest_ratio`, opportunity ranking weighted by liquidity using `volume_traded` and stock, hour-of-day and league-age seasonality, anomaly flags for cornering, detection of routing and ratio-cap mispricings, and a PoE 1 port of the Bellman-Ford cycle finder with volume floors and persistence filters. None of these exist for PoE 1 today. All of them depend on first settling the open semantics question in [issue #1](https://github.com/stdmitry/pathofflipper/issues/1): which way the ratios point, what the stock extrema measure, and whether the two volumes describe the same trades. Hourly aggregates cannot show live depth, so every "opportunity" should be presented as indicative and at least an hour stale.

Three practical adjustments follow. First, if the project ever adds live confirmation through `/api/trade/exchange`, treat it as a **user-initiated, one-pair-at-a-time lookup** and not a poller. The budget is about 30 calls per 5 minutes per IP with a 30-minute lockout, and the endpoint is undocumented, so automated polling falls under ToS 7f/7i. Copy APT's pattern: start conservative, rebuild limiters from every response's headers, and refuse long waits. Second, the current `User-Agent: pathofflipper/<version> (contact: …)` is not the documented `OAuth {clientId}/{version} (contact: …)` form. Without a registered client this is the closest honest option, and it complies with poe.ninja's request. It should stay transparent, never disguised. Third, the docs define a `service:cxapi` scope even though the CDN endpoint works anonymously. The collector should expect that GGG could later require OAuth, and should add GGG's required non-affiliation disclaimer to any published UI. Features that crossed into the client, such as OCR of the Market Ratio panel, auto-filled order fields or auto-whispers, would trade the project's cleanest property for a feature poe-flipper already offers and nobody uses.

## Conclusion

The price-check overlay genre has solved item pricing and handed currency pricing to GGG's hourly digest. As a result, the most valuable PoE 1 currency data is now a public, immutable, hour-lagged feed that most consumers read only for its latest value and then discard. The flipping tools that exist either act on a single screen or target PoE 2. pathofflipper's advantage is therefore less about speed or live data and more about memory: it is the only PoE 1 archive of the exchange's own trade history. Its analytics can answer questions that poe.ninja structurally cannot, such as how wide a spread usually is, when it opens, and whether it lasts.

The policy landscape supports that direction. GGG's enforcement history shows the real risk for API clients is lockouts from over-requesting, not game bans, while automation that touches the client is the one hard line. A read-only, website-style analytics tool that leaves every order to a human is compliant by construction and scales without the rate-limit budget. The main unknowns are GGG's actions, not the project's: whether it gates the digest behind `service:cxapi`, prunes old history, or ever exposes current-hour data. Archiving continuously now is the hedge against all three.
